# PM 올인원 보드 — 배포 가이드

프로젝트보드(마일스톤·이슈·승인·회의록)와 루틴보드(상태보고·워크로드·리스크·회고) 8가지 기능을
프로젝트 하나·링크 하나로 통합한 무료 웹사이트입니다. "실행 현황"과 "정기 루틴" 두 탭으로 나뉘어 있습니다.
다른 모듈들과 똑같은 구조입니다: **도메인 = Vercel, 창고(DB) = Supabase, 프런트/백엔드 = 이미 작성된 코드**.
코드는 이미 다 만들어져 있으니, 아래 순서대로 계정만 연결하면 됩니다. 전체 20분 정도 걸립니다.

---

## 시작하기 전에 — 압축 파일 사용법

1. 전달받은 `allinoneboard.zip` 파일을 다운로드합니다.
2. 압축을 풉니다. (Windows는 파일을 우클릭 후 "압축 풀기", Mac은 파일을 더블클릭하면 됩니다.)
3. `allinoneboard` 폴더가 하나 생기고, 그 안에 이 README를 포함한 파일들이 들어 있습니다. 이 폴더가 곧 여러분의 웹사이트 전체입니다 — 폴더 안 파일 이름이나 구조는 바꾸지 마세요.
4. 아래 1단계부터 순서대로 따라가면 됩니다. 코드를 직접 수정할 필요는 전혀 없고, 딱 두 군데(`config.js`의 두 줄)만 채워 넣으면 됩니다.

---

## 1단계 — Supabase(창고) 만들기 (5분)

1. [supabase.com](https://supabase.com) 에서 무료로 가입합니다. (다른 모듈을 이미 만들어보셨다면 같은 계정을 그대로 쓰고, **새 프로젝트**만 하나 더 만들면 됩니다.)
2. "New Project"를 눌러 프로젝트를 하나 만듭니다. (리전은 Northeast Asia (Seoul) 추천)
3. 프로젝트가 만들어지면 왼쪽 메뉴에서 **SQL Editor**를 클릭합니다.
4. 이 폴더 안의 `supabase-schema.sql` 파일을 열어 내용을 전체 복사한 뒤, SQL Editor에 붙여넣고 **Run**을 누릅니다.
   - 성공하면 `aob_projects`, `aob_milestones`, `aob_issues`, `aob_feedback_items`, `aob_feedback_comments`, `aob_meetings`, `aob_action_items`, `aob_reports`, `aob_tasks`, `aob_risks`, `aob_retro_items` 열한 개의 표(테이블)가 만들어집니다. 이 접두사(`aob_`)는 프로젝트보드(`pjb_`)·루틴보드(`rb_`)와 겹치지 않는 새 이름이라, 두 모듈을 이미 설치해둔 **같은 Supabase 프로젝트**에 그대로 추가 설치하셔도 안전합니다 — 새 프로젝트를 따로 만들 필요 없이 기존 SQL Editor에 붙여넣고 Run 하시면 됩니다.
5. 왼쪽 메뉴에서 **Settings → API Keys**로 이동합니다. (대시보드가 최근 개편되어 예전 "API" 메뉴명이 "API Keys"로 바뀌었습니다.)
6. **Project URL**과 **anon** `public` 키를 복사해둡니다. ⚠️ 새로 추가된 `sb_publishable_...` 키는 아직 일부 코드와 호환성 문제가 있어 오류가 날 수 있습니다 — 반드시 `eyJ...`로 시작하는 예전(레거시) anon key를 사용하세요. 화면에 안 보이면 "Legacy keys" 표시가 있는 곳을 펼쳐보세요.

## 2단계 — 코드에 연결 정보 붙여넣기 (2분)

1. 이 폴더의 `config.js` 파일을 텍스트 에디터(메모장 등)로 엽니다.
2. 아래 두 줄을 방금 복사한 값으로 바꿔줍니다.

```js
window.SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";   // ← Project URL 붙여넣기
window.SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";           // ← anon public 키 붙여넣기 (eyJ...로 시작하는 레거시 키. 새 sb_publishable_ 키는 호환성 문제로 비권장)
```

3. 저장합니다.

## 3단계 — Vercel(가게 운영)에 배포하기 (10분)

가장 쉬운 방법은 GitHub을 거치는 방법입니다.

1. [github.com](https://github.com) 에 가입되어 있지 않다면 무료로 가입합니다.
2. 새 저장소(Repository)를 하나 만들고, 이 `allinoneboard` 폴더 전체를 업로드합니다.
   - GitHub 웹사이트에서 "Add file → Upload files"로 폴더 안 파일들을 그대로 드래그해서 올리면 됩니다.
3. [vercel.com](https://vercel.com) 에서 GitHub 계정으로 가입/로그인합니다.
4. "Add New → Project"를 누르고, 방금 만든 GitHub 저장소를 선택합니다.
5. Framework Preset은 **Other**(또는 감지되지 않음)로 두고, 별도 설정 없이 **Deploy**를 누릅니다.
   - 이 사이트는 순수 HTML/CSS/JS라 빌드 과정이 필요 없습니다.
6. 1~2분 뒤 `https://프로젝트이름.vercel.app` 같은 주소가 생기고, 바로 접속해서 테스트할 수 있습니다.

## 4단계 — 직접 확인해보기

1. 배포된 주소로 접속해서 "새 프로젝트 만들기"에 아무 이름이나 입력해봅니다.
2. "실행 현황" 탭에서 마일스톤 하나, 이슈 하나, 피드백/승인 요청 하나, 회의 하나를 각각 추가해봅니다.
3. "정기 루틴" 탭으로 전환해서 상태보고서 하나, 업무 하나, 리스크 하나, 회고 항목 하나를 각각 추가해봅니다.
4. 두 탭에서 상태 버튼을 눌러 상태가 바뀌는지 확인합니다.
5. 상단의 "전체 현황 마크다운으로 복사" 버튼으로 여덟 가지 내용이 모두 요약되어 복사되는지 확인합니다.
6. 만약 오류가 뜬다면 대부분 `config.js`의 URL/키가 잘못 붙여넣어졌거나, 1단계의 SQL이 실행되지 않은 경우입니다.

## 5단계 — 검색 노출 + 애드센스 신청

1. Vercel 배포 후 [Google Search Console](https://search.google.com/search-console)과 [네이버 서치어드바이저](https://searchadvisor.naver.com)에 사이트를 등록합니다.
2. 콘텐츠 페이지(`guide/` 폴더 6개, `faq.html`)가 이미 있어 애드센스 심사에 필요한 "실질적인 텍스트 콘텐츠" 요건을 채웁니다. 더 필요하면 저에게 "PM 올인원 보드에 가이드 글 하나 더 써줘"라고 요청하시면 같은 형식으로 만들어드립니다.
3. [Google AdSense](https://www.google.com/adsense)에 사이트를 등록하고 심사를 신청합니다. 승인까지 보통 며칠~몇 주 걸립니다.
4. 승인 후 발급받는 광고 코드를 `index.html`, `board.html`, `guide/*.html` 등 원하는 페이지의 `</head>` 직전이나 본문 원하는 위치에 붙여넣으면 광고가 노출되기 시작합니다.

## 6단계 — 커스텀 도메인(선택)

Vercel 프로젝트의 **Settings → Domains**에서 직접 구매한 도메인을 연결할 수 있습니다. `.com` 도메인은 연 1만~2만 원대부터 구매 가능합니다. 없어도 `.vercel.app` 주소로 계속 운영 가능합니다.

## 참고 — 프로젝트보드·루틴보드와의 관계

이 모듈은 기존 프로젝트보드(A그룹 4종)와 루틴보드(B그룹 4종)를 프로젝트 하나·링크 하나로 합친 버전입니다.
다만 테이블은 기존 두 모듈의 `pjb_`/`rb_`를 그대로 이어받지 않고, **`aob_`라는 새 접두사**로 11개 테이블을 완전히 새로 만듭니다.
그래서 프로젝트보드·루틴보드와 같은 Supabase 프로젝트에 함께 설치해도 테이블이 겹치거나 데이터가 섞이지 않으며,
세 모듈은 서로 독립된 데이터를 가진 별개의 상품으로 동작합니다. 그 대신 기존 프로젝트보드/루틴보드에 이미 쌓인 데이터는
자동으로 넘어오지 않습니다 — 그대로 옮겨오려면 `insert into aob_... select ... from pjb_...`(또는 `rb_...`) 형태의
마이그레이션 스크립트가 필요합니다. 필요하시면 요청해주세요.

## 이후에 사이트를 늘리고 싶다면

똑같은 구조(Supabase + Vercel + 정적 HTML)로 "내가 불편했던 것" 하나씩을 골라 사이트를 늘려가면, 관리 부담 없이 여러 개의 사이트가 동시에 돌아가는 구조를 만들 수 있습니다. 다음 사이트를 만들 때도 저에게 요청해주시면 이번처럼 코드와 배포 가이드를 함께 만들어드립니다.

## 제거(언인스톨)가 필요하다면

같은 폴더의 `uninstall-schema.sql`을 Supabase SQL Editor에 붙여넣고 Run 하면 이 모듈의 테이블만 삭제됩니다. 다른 모듈과 같은 프로젝트에 함께 설치했더라도 테이블명 접두사가 서로 달라 다른 모듈 데이터에는 영향이 없습니다. 프로젝트 자체를 더 이상 쓰지 않는다면 Supabase 대시보드에서 프로젝트를 통째로 삭제해도 됩니다.
